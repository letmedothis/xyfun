# NET-001

## Original Issue

Remote Code Execution via tvbox `new Function` in file handler. The content of `index.js` files within APP_FILE_PATH is loaded and executed via `new Function()` without sandboxing.

## Root Cause

The tvbox make endpoint at `src/main/services/FastifyService/routes/v1/file/tvbox.ts:113` used `new Function()` to execute arbitrary JavaScript code from `index.js` files. An attacker who could write a file to APP_FILE_PATH could achieve arbitrary code execution in the main process.

## Fix

Removed the `new Function()` execution entirely. The endpoint now only reads pre-existing `index.json` files directly. If `index.json` doesn't exist, an empty response is returned.

## Files Changed

- `src/main/services/FastifyService/routes/v1/file/tvbox.ts`

## Behavior Before

1. Request arrives at `/api/v1/file/film/make/:type/*`
2. If `index.js` exists, its content is executed via `new Function()`
3. The result is saved to `index.json`
4. `index.json` content is returned

## Behavior After

1. Request arrives at `/api/v1/file/film/make/:type/*`
2. Only `index.json` is read directly
3. If `index.json` doesn't exist, empty response is returned
4. No code execution occurs

## Regression Risk

LOW - The endpoint now requires `index.json` to be pre-generated. If users relied on the `index.js` execution to auto-generate `index.json`, they will need to pre-generate it.

## Remaining Risk

If `index.json` contains malicious data, it could still cause issues in the renderer, but this is a data validation issue, not RCE.
