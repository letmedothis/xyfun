# NET-002

## Original Issue

Remote Code Execution via t3Catopen dynamic import from remote URL. The adapter fetches code from a user-configured remote API URL and executes it via dynamic `import()` using a data URI.

## Root Cause

The CMS adapter system is designed to fetch and execute remote code. The `t3Catopen` adapter fetches JavaScript code from `this.api` (a user-configured URL), base64-encodes it, and imports it as a module with full Node.js worker process capabilities.

## Fix

**NEEDS_PRODUCT_DECISION** - This is an architectural feature of the CMS adapter system. The code execution is by design. A full fix would require:

1. Code signing for remote scripts
2. Sandboxed execution environment (V8 Isolate)
3. URL validation (HTTPS only)

Partial mitigation added: Security logging in CdpElectron.ts for script execution.

## Files Changed

- `src/main/services/CdpElectron.ts` (logging only)

## Behavior Before

Remote code fetched and executed without any logging or validation.

## Behavior After

Remote code still executed (by design), but security warning logged when custom scripts are executed in Puppeteer pages.
